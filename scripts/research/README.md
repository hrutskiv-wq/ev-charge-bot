# scripts/research — разові дослідницькі скрипти

Фаза 0 роадмапу, напрям «карта-довідник»: чи вистачає відкритих даних
(OpenChargeMap + OpenStreetMap), щоб показати водієві мапу зарядок України,
не купуючи комерційний фід і не обходячи станції ногами.

**Прогін: 30–31.07.2026.** Це **не прод-код**: ні в cron, ні в systemd, ні в
імпортах застосунку. Єдина залежність від коду проєкту — `haversine_km` з
`app/services/geo.py`, узятий навмисно (див. нижче).

---

## Головне про числа

**Числа в результатах — зріз на дату прогону, і вони застарівають.** OCM
приймає правки щодня, OSM — щогодини. Будь-яка цифра з тих прогонів (скільки
POI по Україні, який відсоток має оператора, наскільки OSM додає понад OCM)
за пів року буде іншою, і посилатись на неї як на поточний стан не можна.

Повторюваний тут **не результат, а прогін**. Цінність цієї теки — методика:
пороги, евристики й критерії, за якими числа рахувались. Якщо їх не
зафіксувати, наступний вимір дасть інші цифри не тому, що змінились дані, а
тому, що змінився спосіб рахувати — і два виміри стануть непорівнюваними.

Тому нижче описано **як рахується**, а не **скільки вийшло**.

## Методика — три рішення, які визначають усі числа

### 1. «Станція має оператора»: `OperatorID` присутній **і != 1**

В OCM `OperatorID = 1` — це `Unknown Operator`, плейсхолдер, а не назва
компанії. Якщо рахувати наївно «поле заповнене → оператор відомий», покриття
метаданими завищується на весь обсяг записів з плейсхолдером.

Для OSM аналог — присутність тегу `operator`.

Ознака входить у ширший критерій «запис має ХОЧ ЯКІСЬ корисні метадані»:
конектор **АБО** потужність **АБО** оператор. Саме `АБО`, а не `І` — для мапи
корисний навіть частково заповнений запис.

### 2. Легальність використання: `IsOpenDataLicensed = true` у `DataProvider`

OCM агрегує дані від багатьох постачальників, і **не всі з них дозволяють
повторне використання**. У результатах загальна кількість і кількість
придатних до легального використання рахуються **окремо**, бо в продукт може
піти лише друга.

Це критерій ліцензії, а не якості: запис може бути повний і точний, але
непридатний, якщо його постачальник не під відкритою ліцензією.

### 3. Дедуплікація OCM ↔ OSM: union-find, поріг 100 м

Два джерела описують ті самі фізичні станції, тому валова сума OCM + OSM —
завжди завищення. Пари точок ближче **100 м** вважаються однією станцією.

Об'єднання — **union-find по всіх парах разом**, а не перевірка «чи має
OSM-точка OCM-сусіда». Різниця істотна: трикутник OCM–OSM–OSM, де всі троє в
межах 100 м, при наївному підході дає дві станції замість однієї.

Відстань — `haversine_km` з `app/services/geo.py`, тобто **та сама функція,
якою прод шукає станції поруч**. Метрику навмисно не переписували: інакше
дослідження міряло б одне, а продукт показував інше.

## Скрипти

Порядок має значення — пізні читають те, що зібрали ранні.

| Скрипт | Що робить |
|---|---|
| `ocm_ua_count.py` | Збирає POI OpenChargeMap по Україні з репозиторію `ocm-export`; рахує загалом і окремо — під `IsOpenDataLicensed` |
| `overpass_count.py` | Найпростіший: лише `out count` з Overpass, скільки `amenity=charging_station` по Україні. Без аргументів, друкує сиру відповідь |
| `overpass_full.py` | Те саме, але **повні** дані — координати й теги (`out body center`), у файл для подальшої обробки |
| `ocm_osm_overlap.py` | Перетин двох наборів: скільки OSM-станцій мають OCM-сусіда в межах 100 м. Дає **чистий приріст** OSM понад OCM, а не валову суму |
| `city_coverage.py` | Покриття по 8 містах у радіусі 15 км від центру: OCM, OSM і дедуплікований набір, плюс скільки записів мають корисні метадані. Для Львова додатково пише CSV для ручної звірки |
| `overpass_kharkiv_meta.py` | Перевірка гіпотези «Харків — аномалія через війну»: тягне `out meta` (дата останньої правки) для відомих OSM-нод, щоб відрізнити довоєнний імпорт без подальших правок від даних, які підтримують і після 2022-02-24 |

Приклад ланцюжка:

```bash
python scripts/research/ocm_ua_count.py --cache-dir ocm_cache
python scripts/research/overpass_full.py --out osm_raw.json
python scripts/research/ocm_osm_overlap.py \
    --ocm ocm_cache/UA_pois_flat.json --osm osm_raw.json --sample-out sample.json
python scripts/research/city_coverage.py \
    --ocm-dir ocm_cache/UA --referencedata ocm_cache/referencedata.json \
    --osm-raw osm_raw.json --lviv-csv lviv.csv
```

`city_coverage.py` і `ocm_osm_overlap.py` **мережу не смикають** — працюють на
вже завантаженому кеші. Повторний прогін виміру не означає повторного
скачування.

## Два практичні застереження

- **`ocm-export` не клонувати цілком.** Репозиторій ~350 МБ і сотні тисяч
  дрібних файлів по всіх країнах, повний `git clone` таймаутить. Тягнеться
  лише `data/UA` через GitHub contents-API. Для UA це вкладалось у ліміт 1000
  записів на відповідь, тому пагінації в скрипті немає — для більшої країни
  її доведеться дописати.
- **`overpass-api.de` інколи віддає 504** під навантаженням. Це не помилка
  запиту — просто перезапустити.

Обидва скрипти ходять у мережу з `User-Agent`, що містить контакт: така
вимога в Overpass, і без неї публічний інстанс має право різати запити.
